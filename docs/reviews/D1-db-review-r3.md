## Checked and correct

**Grants and statements.** Every trace_api statement in `store.ts:218-237` passed the executor's permission checks as `trace_api`: `private.resolve_invitation_by_hash(text)`; selects on `invitations` (grant `invites_sessions.sql:955-957`), `test_versions` (`d1_authoring.sql:1122-1123`), `notice_versions` (`:1097`), `consents` (`invites_sessions.sql:997`); the five conditional UPDATEs (`moveStatus` with bound `$4::text[]`, `declareAdult`, `setSessionId`, `markStarted`, `markExpired`; columns `:961`); the consent INSERT … ON CONFLICT (`:1001-1002`, arbiter `:116`); `private.media_link_grant/media_view_grant(uuid, uuid, text, text[], uuid)` (`d1_media_audit.sql:101,152`). `has_column_privilege(…link_token_hash…)` is false for trace_api and authenticated; `media_objects.r2_key` false for authenticated; `sessions` false for trace_api.

**Transaction layer.** Constant SQL, every value bound; the text[] literal is built only from `[a-z_]` enum labels (`store.ts:255-258`); the amr literal is fully quoted (`media-link.ts:136-137`). Each unit is one transaction: `set local role trace_api`, `set_config(…, true)` for `trace.api_org_id` and a uuid `trace.request_id`, COMMIT before any answer. `max: 1`, `prepare: false` (pooler-safe).

**Invitation state machine.** Each move matches the guard: `sent` only from `created` and after the outbox write; `otp_verified` from `created|sent`; `started` only by `sessionStarted` with session id, `otp_verified`, adult true and a consent; `expired` only from `created|sent|otp_verified` with `session_id is null` (L-32); `blocked_age` only via the guard's self-declared rule; `session_id` set once, after the consent. Retries are idempotent (stored `started_at` returned, consent replay no-op, lost `setSessionId` race re-read, outbox keys `invite:<id>` and `otp:<key>`).

**Org paths.** Every insert and update column is inside the `authenticated` grants; RLS USING clauses match the routes' filters; guard SQLSTATEs map to 409 (23505), 404 (42501/23503) and 400/422 (23514). **Reports and cards** stay in public tables, filtered by `session_id` and id; the integrity card is read only when `meets_cutoff = true` and `reviewed`; report, timeline and queue lists ask for cap+1 and fail closed. **Media:** the grant runs in its own transaction before the DO issue; the burn precedes `media_view_grant`; only the DB-returned key is streamed, after COMMIT; one audit row per granted call with the viewer as actor.
