- **Reviewed:** on `d1/integration` since `09ccfa4`: the ES256 key ops script (`9429559`, `19152dc`, `e0121f3`), the staging-deploy rework (`5a775e8`, `6640b42`), the recruiter CSP API origin and pinned ports (`14dea42`, `14782e4`, `511713d`, `0f842cf`), the carried DB fixes (`cfd3a67`) and, low priority, the DC-D5/D6 spike (`3a50093`, `cac21d6`, `6030a30`).
- **Reviewer:** Opus `security-reviewer`, read-only (no network; check-workflows rules run in memory on edited copies of ci.yml).

## Verdict: PASS WITH NOTES (no Blocking or High; one Medium, five Low, three Info)
Clean: the key script never prints or leaks the private key (fixed messages, `wx` + 0600, out-dir outside every git tree via realpath, kid form, array output, rotation refusals; the README puts only paths on the command line). The deploy `if:` cannot be reached from a pull request or a tag; secrets are step-scoped and every `--var` comes from `vars.*`; wrangler splits `--var` at the first `:` (`cli.js:219861`), so the JWK JSON survives. The CSP api origin is one staging label with no port, path, credentials or wildcard, never echoed, function replacement (no `$&` injection). DB: retired versions keep `published_at` and only drafts can be deleted, so the first-publish predicate cannot be bypassed; `test.retire` carries the caller as actor and `{version_no}` only.
