## 1. Scope and lead decisions
### 1.1 The slice (exit gate, build-order.md:37)
A recruiter creates a test (written + MCQ) and invites a candidate by link. The candidate takes it in the browser with a server-held timer, a start photo and autosave. The result shows **Answer Quality** (0–100, mock grader) and the **Integrity band with an evidence timeline as two separate results**. A reviewer opens the report. It is deployed on staging (`*.workers.dev` / Pages), with synthetic data only. **Exit gate:** the full flow passes an automated E2E test on staging, plus a 5-minute screen recording.

## 3. Data model (migrations are lead-only)

Conventions are build-notes §4 and `specs/m0b-tenancy.md` §3 unchanged: `org_id uuid not null` + `unique (org_id, id)` + a first-column `org_id` index (MT-2); composite FKs `(org_id, x_id)`; RLS on; one policy per operation and role set (MT-11), never `FOR ALL`, never `PUBLIC`; explicit grants, none to `anon`; invariants in triggers/CHECKs; timestamps `timestamptz not null default now()`; length CHECKs on every text column; no column name matching MT-3 (`dob`, `birth`, `honesty`, `trust_score`, `cheat`, `emotion`, `voiceprint`, `face_template`, `gaze_flag`; `reject` is banned in `integrity`, and D1 also avoids it everywhere, see I-2). Postgres is reached by `authenticated` (recruiter app, PostgREST; `services/api` org endpoints pass the user's JWT through, so RLS decides), by server workers and by `services/api`'s own role `trace_api` through `SET LOCAL ROLE` (ADR-029). **The candidate never reaches Postgres in D1 (D1-3):** `trace_candidate` and `anon` hold nothing; the api acts for the candidate through `trace_api` (§3.3b). Everything below is *synthetic-only* (D1-1).

PostgREST exposes only `public` (`supabase/config.toml` `[api] schemas`), and MT-7 forbids SECURITY DEFINER outside `private`. So a **user-facing privileged step is a guarded table write** (BEFORE trigger, as in M0b), not an RPC; **worker- and api-facing steps are `private` functions** called over SQL after `SET LOCAL ROLE`. **Roles:** `trace_worker`, `trace_quality_worker` and `trace_integrity_worker` as in R-6; new NOLOGIN role `trace_api` (migration 2, `create role … if not exists`, M0b §2.3). MT-14 (a) forbids `rolcanlogin` on any `trace_*` role, so each is entered from an operator-created login role that is not named `trace_*` (`api_login` for `trace_api`; `grant trace_api to api_login with inherit false, set true`; passwords by the operator runbook, never in a migration). `api_login` is a member of no other `trace_*` role (MT-14 (f)). Secret: `API_DB_URL` (Worker secret of `services/api`; the `check-staging-secrets` allow-list for `api` gains it, §7.2).

### 3.2 Tables
Notation: **W** = who writes (a role, or "guard trigger"). `ws` = `workspace_id`, copied from `tests` (cards: from `sessions`) by a BEFORE INSERT trigger on every test-descendant table and immutable (composite FK `(org_id, workspace_id) → workspaces`), so workspace-scoped recruiters (M0b D16b) are fenced on every child table. **Freeze triggers** (`F`) are SECURITY DEFINER, `ENABLE ALWAYS` (replica mode cannot skip them, as for `audit_log`), fire for workers too, and have **no operator bypass** (Q20).

**Decision: no `items` table in D1.** D1 has no pools, reuse, import or AI drafting, so item identity adds nothing. `item_versions` carries `item_id uuid not null default gen_random_uuid()` (a stable identity with no FK). M1 adds `items`, the FK, and relaxes `section_id` to nullable; no D1 column is dropped (additive).

## 10-DB. Database edge cases
| Case | Behaviour |
| --- | --- |
| Two recruiters publish the same draft at once | `for no key update` on the `tests` row serialises; the second sees `status='published'` and the guard refuses (`TRACE_GUARD`); one `test.publish` audit row and one creator assignment (`on conflict do nothing`) |
| Edit after publish, or change the cutoff | all child freeze triggers refuse for every role including workers and replica mode, and `quality_cutoff` is part of the frozen version row; the recruiter creates a new draft version (one open draft per test, partial unique); existing invitations keep their pinned version and cutoff |
| Re-publish / retire while invitations exist | retiring leaves pinned invitations valid (the DO holds the package); new invitations may pin only `published` |
| Two invitations created in parallel | the label trigger locks the `tests` row, so labels are gap-tolerant but unique (`Candidate n`); a rollback may leave a gap, never a duplicate |
| Duplicate `link_token_hash` (collision or replay of an insert) | global unique violation `23505`; the API retries with a new token; no row |
| `trace_api` runs without `api_org_id` (a bug), or with another org's | RLS returns no rows / refuses writes; the token-hash lookup is the only cross-org read and returns one invitation by an unguessable hash |
| Consent replayed (double click, retry) | `unique (org_id, invitation_id, event)`: `on conflict do nothing`, the api re-reads the same row and the same `session_id`; a second `session_id` write is refused (set-once) |
| Consent attempted before OTP or age, or on a blocked invitation | the consent guard refuses; no row, so no `session_id`, no `started`, no session (Q36, rule 9) |
| Invitation revoked mid-session | `authenticated` may revoke only from `created|sent`, so a revoke cannot land after OTP; revocation before OTP is enforced at the edge by `services/api` (runtime spec). If a revoke wins before the OTP but the DO already started, `mirror_session` finds `revoked` (terminal), stores nothing and returns `'rejected_invitation'` for a dead letter and an operator look (R-14) |
| Duplicate / replayed / reordered mirror messages | `mirror_seq` ≤ stored → `'duplicate'`, no writes; the `(session_id, mirror_seq)` `idempotency_keys` row and the natural unique keys make a partial retry safe; a gap is accepted (forward-only, not contiguous) |
| Mirror arrives before the media row, or the photo upload fails | the start photo uploads through the edge Worker to R2 first; `media_objects` is written only by the mirror and only for an R2 object whose key the message names. A partial or abandoned upload leaves an orphan R2 object with no row (swept by M7); a session may mirror with no photo row only if the message says `photo_missing` (camera declined or skipped, R-11), and the report shows "no start photo" (never a failure) |
| Clock skew | the DB never compares DO timestamps to `now()`: CHECKs order only DO-supplied times (`submitted_at ≥ started_at`, `server_deadline_at > started_at`). `created_at` is DB time and is never used for the deadline. The DO's alarm and +60 s grace live in the runtime spec |
| Submit after the deadline | stored as `auto_submitted` / `submit_kind='deadline'` exactly as the DO says; the DB does not re-derive it |
| Concurrent grading and integrity jobs for one session | independent: separate schemas, roles, and natural unique keys `(org_id, session_id)` / `(org_id, session_id, ruleset_version_id)`; a re-run is `ON CONFLICT DO NOTHING`, never an update |
| Integrity job arrives before the quality card | the job has no `shortlisted` message field (it cannot default to "reviewed"): it inserts the result and an `awaiting_quality` card, finds no `quality_cards` row and retries; flags and the flip wait for `meets_cutoff`. If the quality job dead-letters the card stays `awaiting_quality`, invisible to org roles, and the UI shows "Pending" (S4) |
| Below-cutoff session | flags inserted `not_used`, no timeline entries, card flipped to `not_reviewed_below_cutoff`; org roles read only `quality_cards`, so the band cannot leak through PostgREST (rule 6). A null cutoff counts as reviewed |
| Report attached twice or out of order | `reports_set_once` accepts each FK column once, in either order, from its own worker only; a second attach or a change is refused; the composite FKs refuse a card of another session |
| Media link replayed, or the viewer loses access between issue and fetch | the api burns the `jti` in its DO on first fetch (a second fetch never reaches Postgres); `media_view_grant` re-checks membership and assignment on the one fetch, so a removed or unassigned viewer gets no key and no `media.view` row |
| Org suspended mid-run | worker policies only bind `job_org_id()`; the recruiter-facing policies already hide a suspended org (M0b); a mirrored session still lands |
| Cross-org id in a payload | composite FKs and `job_org_id()` / `api_org_id()` bind every row; the functions assert `p_org_id = job_org_id()` |
| Hard delete of a referenced auth user, test, version or invitation | `restrict` FKs; no DELETE grant; erasure is the M7 pipeline |

## 4. Candidate runtime

Scope: everything between the invite link and the receipt. The recruiter side (tests, invitations, the demo outbox) is §3 and §6; the jobs that read a submitted session are §5. "(inference)" = chosen here, not stated in a decision. All wire contracts are zod schemas in `packages/shared/src/contracts-candidate.ts`, exported as `@trace/shared/contracts/candidate` (strict objects). Database access by the candidate path is one login role, `trace_api` (secret `API_DB_URL`, S5); the candidate never reaches Postgres itself (D1-3).

### 4.1 Flow and state machines

**Invitation states** (`invitations.status`; there is no `rejected`):

| From | To | Written by | Trigger |
| --- | --- | --- | --- |
| (new) | `created` → `sent` | `services/api` org endpoints (§6, user JWT) | recruiter creates, then sends (mock Messaging writes the demo outbox) |
| `sent` | `otp_verified` | `services/api` as `trace_api` | first successful OTP verify (the edge calls `lobbyMint`). Later logins (resume) leave the state alone |
| `created`, `sent`, `otp_verified` | `blocked_age` | `trace_api` (or the invitation insert trigger for the inviter's answer) | `ageDeclare(adult=false)`, or `adult_confirmed_by_inviter = false`. Sticky and terminal |
| `otp_verified` | `started` | `trace_api` | first `sessionGrant` (sets `started_at`, the timer origin, §4.4) |
| `started` | `submitted` | `workers/jobs` mirror (`trace_worker`) | the mirror stage (§5.1) for a `submitted` or `auto_submitted` session |
| `created`, `sent`, `otp_verified` | `expired` | `trace_api` | lazily, when `now > expires_at` is seen at resolve / OTP / grant. A `started` session is **not** cut short |
| `created`, `sent` | `revoked` | `authenticated` via §6 (R-14) | recruiter action. A revoke after OTP is not possible in D1; a live revoke is M3a |

Terminal: `submitted`, `expired`, `revoked`, `blocked_age`. A dead link stops new logins and grants only; an in-progress session runs to its deadline because the DO never reads Postgres.

**Session states** (inside the DO; mirrored): `in_progress`, `submitted` (candidate action), `auto_submitted` (alarm). No state carries an outcome, score or band. `paused`, `suspended_awaiting_reschedule`, `withdrawn` are M3a.

**Step order (D1-13)**; edge routes call `CandidateRpc` methods (§4.2):

| # | Step | Client calls | Server effect |
| --- | --- | --- | --- |
| 1 | Link | `POST /v1/invite/resolve` | read only: state, test title, duration. No OTP sent, no camera |
| 2 | OTP | `POST /v1/otp/request`, `POST /v1/otp/verify` | `InviteOtpDO` (edge) issues and verifies; the code goes to api `messagingSend`, which writes the demo outbox; after a successful verify the edge calls `lobbyMint` and api mints the **lobby** token |
| 3 | Age | `POST /v1/lobby/age` | stores `adult_confirmed` + source; `false` → `blocked_age`, 403 `not_eligible`, nothing else is created |

### 4.3 Candidate tokens (D1-3, ADR-030)

Compact JWS, header `{alg:'ES256', typ:'JWT', kid}`; claims exactly ADR-030 §7: `{sub, candidate_id, invitation_id, org_id, typ, nonce, iat, exp}` (zod strict, `sub === candidate_id`, integer times, `nonce` ≥ 16 chars). `candidate_id` is the random v4 uuid stored on the invitation (R-10).

| `typ` | Minted by | Lifetime (`exp - iat`) | Valid on | Replay control |
| --- | --- | --- | --- | --- |
| `lobby` | api `lobbyMint` | 30 min (inference), cap 1800 s | `/v1/lobby/*`, `/v1/session/start` | the edge generates a nonce at each OTP verify and stores its hash in `InviteOtpDO`; the edge compares it on every lobby request before the RPC, so a new login kills the old lobby token. Cleared when a session token is granted |
| `session` | api `sessionGrant` | `started_at + durationSeconds + 3600 − iat`, cap 10 800 s; not re-issued in D1 (no deadline moves; deviates from ADR-030's "DO asks the issuer", a simplification) | `/v1/session/*` | `nonce` hash held by `SessionDO`, compared on every request, rotated at each `sessionGrant` (one active device, Q41), cleared on submit. A reload uses `attach` with the same token |
| `portal` | not minted in D1 | n/a | rejected everywhere | n/a |

**Verification at the edge**, rejecting 401 on the first failure: `alg` equals `ES256` (anything else, including `none`, before the signature); `kid` in `CANDIDATE_TOKEN_PUBLIC_JWK` (unknown → reject); signature via Web Crypto; strict claim shape; `typ` equals the route's; lifetime cap; `exp > now` and `iat <= now + 60 s`; nonce hash check (`InviteOtpDO` for `lobby`, `SessionDO` for `session`). The DO id and every id used downstream come from verified claims, never from the URL or body. `kid` form `d1-YYYY-MM`; the var holds the previous key for at least the 3 h session cap during rotation; only the current `kid` signs. The private JWK is generated by an ops script (lead, `scripts/ops/`) and set as an api secret. The raw link token is 32 random bytes, base64url, in the URL **fragment** (`/i#<token>`), cleared by the app with `history.replaceState`; only `sha256(token)` is stored (`invitations.link_token_hash`), looked up by api.

### 4.4 `SessionDO` protocol

**Test package** (read from R2 once at start). `packages/{test_version_id}.json` in `trace-packages-<env>`, written by api at publish, immutable, verified against `packageSha256` from the grant, ≤ 256 KB, strict `TestPackage` schema: `{v:1, testVersionId, rulesetVersionId, title, language:'en', durationSeconds, pasteBlocked:true, heartbeatSeconds:10, signalCatalogVersion, sections[{id, title, position}], items[{position, sectionId, itemVersionId, kind:'mcq'\|'written', prompt, options?[{id, label}], maxChars?}]}`. **No answer key, rubric, weight or score field exists in the schema.** The DO copies the package into its storage and then reads R2 only to write evidence at submit.

**Storage (SQLite).** `meta` (session/org/invitation/test/ruleset/consent ids, state, `started_at`, `deadline_at`, `submit_kind`, `nonce_hash`, `active_stream_id`, `photo`, `receipt_ref`, `mirror_state`, `mirror_attempts`); `served(position, served_at)`; `streams(stream_id, hw, opened_at)`; `events(stream_id, seq, kind, t_client, t_server, payload)` with primary key `(stream_id, seq)`; `answers(position, text|choice)`. The `session_id` is the one minted by api at consent (R-10); the DO does not mint it.

**Timer.** `started_at` is the grant's `startedAt`; `deadline_at = started_at + durationSeconds`. All times are server times; client `t` values are monotonic offsets kept as T3 context. One alarm at `deadline_at + 60 s` (grace for in-flight saves, plan §12). Events are accepted while `t_server <= deadline_at + 60 s` and the stream's sequence is unbroken; later ones answer 410 `closed`. At the alarm, if `in_progress`, finalise as `auto_submitted` (idempotent). The single alarm slot is reused for mirror retries (next alarm = the earlier of the deadline alarm while in progress and the next mirror retry).

**Start / attach.** `start(grant, photo)`: if a session exists, rotate `nonce_hash` and open a new stream (resume); else create it (`in_progress`) from the package. Rejects `closed` if `now > deadline_at + 60 s`, and refuses unless the grant says `adultConfirmed: true` (D1-12; the DB CHECK is the second gate). `stream_id` is issued by the DO; each start/attach supersedes the previous stream (its events answer 401 `superseded`).

**Events.** One ordered stream per `(session_id, stream_id)`, `seq` from 1, contiguous. `ClientEvent` is a strict union on `kind`:

| `kind` | Payload | Meaning |
| --- | --- | --- |
| `answer.text` | `{item, p, d, i}` | splice on the item's text: keep `p` UTF-16 units, delete `d`, insert `i` (≤ 10 000), derived from the common prefix/suffix of consecutive textarea values. `maxChars` is enforced on the rebuilt length |
| `answer.choice` | `{item, option\|null}` | selected MCQ option, `null` clears |
| `signal` | a §4.6 shape | client-reported browser fact |
| `heartbeat` | `{}` | liveness, every 10 s |

A batch runs in one `transactionSync`: `seq <= hw` is ignored (idempotent resend); the next must be `hw + 1`; the first gap stops the batch with 409 `out_of_order` and `ackSeq = hw`. Rebuild: at submit the DO replays **all** accepted `answer.*` events from empty, in arrival order across streams, and compares with the incremental state and the SHA-256 of each answer in `SubmitReq`; the replay is the final answer. A mismatch is recorded as `replay: 'mismatch'` context (not a band input). Every 25th `answer.text` event carries `len` for an early check.

**Coverage and gaps.** The session is cut into 10 s windows from `started_at` to submit. A window is *covered* if any accepted event (heartbeat included) has `t_server` inside it, or lies inside a `tab_hidden` interval (hidden tabs throttle timers; inference). The DO reports `coverage {activeMs, coveredMs}`. A run of ≥ 3 consecutive uncovered windows is a gap `{from, to}` labelled `connectivity`, never focus loss. The band engine owns the floor (D1-6).

**Submit.** `submit(streamId, finalSeq)`: requires `hw >= finalSeq` (else 409); rebuilds answers; closes the open hidden interval; computes coverage; writes to `EVIDENCE` `sessions/{org}/{session}/final.json` and `sessions/{org}/{session}/events.ndjson` (the full event log; no content); sets `state`, clears `nonce_hash`; derives `receiptRef` = first 8 Crockford-base32 chars of sha256(session_id) (deterministic; the UI shows it as `TR-XXXXXXXX`; unique per org in the DB, a collision fails the mirror loudly); stores the mirror message in `meta`; answers `Receipt {receiptRef, submittedAt}`. A repeat returns the same receipt. The receipt does not wait for Postgres.

**The one mirror message** (`SessionMirrorMessage`, strict, ≤ 100 KB; content stays in R2; **the single contract and the single queue**, S7):

```ts

  jobKey: z.string(),   // `${sessionId}:session_mirror:${rulesetVersionId}`; each stage derives `${sessionId}:${job}:${rulesetVersionId}`, job in mirror|quality|integrity
  sessionId: z.uuid(), orgId: z.uuid(), invitationId: z.uuid(), testVersionId: z.uuid(), rulesetVersionId: z.uuid(), consentId: z.uuid(),
```

The message holds **no signal list**: the integrity job reads signals from the hash-verified `events.ndjson` (S7). The consumer (`workers/jobs`, §5.1) runs three idempotent stages per message. After 5 failures the message goes to the DLQ; `mirror_state` never reads "acked" unless the queue accepted the message.

**Delivery and fallback.** `MIRROR_TRANSPORT = 'queue'`: `MIRROR_QUEUE.send(msg)`. If `send` throws, `mirror_state` stays `pending` and the alarm retries with backoff 5 s, 15 s, 60 s, then every 5 min for 24 h, then `failed` and `session.mirror_failed` is logged. `'service'` (only if Queues are unavailable, DC-D2): the same message goes to `env.JOBS.mirror(msg)` (`MirrorRpc`), which runs the same pipeline function and returns after commit. One pipeline function, two transports; a unit test runs the same fixtures through both.

### 4.5 Start photo (D1-5, rule 8)

- **Device.** After the consent row exists (§4.7), `getUserMedia({video: {facingMode: 'user', width: {ideal: 640}, height: {ideal: 480}}, audio: false})` feeds an offscreen `<video>`. A visible `<canvas>` (no `<video>` on screen, no `blob:` URL) renders each frame through the pure function `blurOutsideOval(frame, oval)` in `src/photo/blur.ts`, which works on `ImageData`-shaped pixel arrays (a down-scale/up-scale plus box blur, no `ctx.filter`, so one deterministic code path in every browser and in tests). The oval is centre 50%/50%, radii 30% of width x 42% of height. The capture canvas is the same canvas, so a pixel outside the oval is never sharp in any buffer that is uploaded. "Take photo" exports `canvas.toBlob('image/jpeg', 0.85)` at ≤ 640x480, shows it with **Retake / Use this photo**, and calls `track.stop()` on every track as soon as the shot is taken or the step is left. The oval is an `aria-hidden` SVG overlay; the instruction is text.
- **AT-D9 pixel test (S10):** `apps/candidate/src/photo/blur.test.ts` (Vitest, node, plain pixel arrays) feeds a checkerboard frame and asserts: every pixel outside the oval has mean absolute neighbour difference < 10% of the source's; every pixel inside the oval equals the source exactly; the output size and oval geometry match; and a wrong-size input throws.
- **Never leaves the device:** the stream and every frame, the unblurred frame, face data (D1 runs no face model), audio (never requested), screen content. Only the processed JPEG is sent.
- **Upload.** `PUT /v1/lobby/photo`, body ≤ 512 000 bytes, `X-Photo-Sha256` = hex SHA-256. Edge: verifies the lobby token; calls `photoPermit` (needs the consent row; `locked` once started); rejects non-JPEG (magic `FF D8 FF`, 415), over the cap (413), dimensions outside 160-1280 px per side (415) and a hash mismatch (400); stores `EVIDENCE.put('media/{org}/{session}/start_photo.jpg', body, {httpMetadata:{contentType:'image/jpeg'}, customMetadata:{sha256, blurred:'1', n}})`. The key is deterministic, so a retake overwrites (max 3). No Postgres write.
- **Record.** At `session/start` the edge `head()`s the object, checks `sha256`, and passes `{key, sha256, bytes}` to the DO, which puts it in the mirror; the mirror stage writes `media_objects` (`kind = 'start_photo'`, `blurred_on_device = true` is client-asserted, T3, R-18).
- **Reviewer view (S9, R-13, R-15).** Rule 8: 5-minute signed link, viewer watermark, every view audited, **evidence needs an assignment for every role**. (1) `POST /v1/orgs/:orgId/reports/:reportId/start-photo-link` (§6.2): api calls `private.media_view_grant(media_id, viewer, aal, request_id, 'link_issued')` as `trace_api`, which checks active membership, role, aal and **assignment** and writes audit `media.link_issued`; api then creates a random 128-bit `jti` in `MediaLinkDO` (`{mediaId, orgId, viewerUserId, aal, exp <= now + 300 s, state:'open'}`) and returns `{url, expiresAt, watermark:{viewerRole, org, issuedAt}}`, `url = /media/{jti}?exp=…&sig=…` with `sig = HMAC-SHA256(MEDIA_LINK_HMAC_KEY, jti|exp)`. (2) `GET /media/:jti` (the only media route, one secret): verifies `sig` (constant time) and `exp`, then `MediaLinkDO.burn(jti)` atomically (**single use**: the second fetch is 404), re-runs `media_view_grant(..., 'view')` for the stored viewer, which re-checks assignment and writes audit **`media.view` per fetch** and only then returns the R2 key; no audit row, no bytes (fail closed). Response `cache-control: no-store`, `content-type: image/jpeg`. The viewer fetches the bytes and draws them to a canvas with a tiled overlay of the viewer's role, org and time (no bare `<img>`; a server-baked watermark is M6). Neither link nor key is logged. Tests: AT-D10.

### 4.6 Client signals (D1-6)

Captured in one module `signals.ts` on the test screen only. Every payload is metadata (item position, length, count, duration): **no pasted, dropped or typed text, no clipboard content, no file names**. Events are stamped `tier: 'T3'` and `validated` by the jobs from the versioned `SIGNAL_CATALOG` in `@trace/shared`; the client sends neither.

| `sig` | Captured how | Payload | Band use (D1-6) |
| --- | --- | --- | --- |

`item` is the item position shown, or `null`. Context-only signals appear on the evidence timeline and never change the band; the rule version, not the event, decides `validated`. Connectivity gaps never create a signal. R-12: the `untrusted_input` precision is unmeasured (browser extensions can dispatch synthetic input); the founder's answer stands, and the report copy says "Input events not produced by the keyboard were recorded", never "cheating". No other signal is captured.

## 5. Results (mirror, Answer Quality, Integrity band, report)

Rule 1 shape: **three jobs, two result writers, one pointer row.** The mirror writes public session facts; `quality/score` and `integrity/band` each read only what they need and write only their own internal schema plus their own public card; `public.reports` holds one FK per card, each set by its own role. No job, view, function or trigger reads both results (D1-9, R-1, MT-5d, MT-14 (f)).

### 5.1 Jobs in `workers/jobs`

**One queue, one message, three stages (S7).** The producer is `SessionDO`; the queue is `trace-session-mirror-<env>` with `max_retries` 5 and DLQ `trace-session-mirror-dlq-<env>` (D1-4; fallback transport in §4.4). The single `queue(batch, env)` handler validates the `SessionMirrorMessage` and `queue/consumer.ts` runs, per message: **mirror → quality → integrity**. Each stage is its own transaction on its own connection and is idempotent under the key `${sessionId}:${job}:${rulesetVersionId}`. If the mirror stage fails, nothing else runs. If quality fails, integrity still runs (it finds no quality card, see below) and the message is thrown for retry after all stages were tried; a retry re-runs only what is missing. After 5 failures the DLQ keeps the message and the UI shows the missing card as "Pending" (operator alert; D1 has no retry UI).

```
workers/jobs/src/
  index.ts, app.ts          neutral: fetch (/health) + queue() + cron
  queue/consumer.ts         neutral: opens one SQL session per stage and INJECTS it (deps.tx: SqlTx), plus the R2 reader (deps.evidence.get)
  mirror/                   trace_worker: handler.ts, writes.ts
  quality/                  trace_quality_worker: handler.ts, score.ts, mcq.ts, written.ts, store.ts
  integrity/                trace_integrity_worker: handler.ts, load.ts, band-call.ts, store.ts
  sweep/                    neutral cron: re-run missing stages (below)
```
`packages/config/test/rule1-separation.test.ts` forbids `quality/**` and `integrity/**` from importing each other or any neutral local file. Neither side opens a connection; `quality/**` imports only its own files, `@trace/shared`, `@trace/vendors`; `integrity/**` only its own files, `@trace/shared`, `@trace/band-engine`. Three login roles, one per stage, each `SET LOCAL ROLE` to its NOLOGIN role; no login role is a member of two worker roles (MT-14). Secrets `JOBS_MIRROR_DB_URL`, `JOBS_QUALITY_DB_URL`, `JOBS_INTEGRITY_DB_URL`. The TCP driver is ADR-031 (R-6).

| Stage | Reads | Writes (as role) | Unique keys |
| --- | --- | --- | --- |
| `mirror` | the message; R2 `final.json` (hash-checked) | **only public session rows** as `trace_worker`: `sessions`, `session_items`, `responses`, `media_objects`, one `reports` row (both card FKs null), invitation → `submitted`, `idempotency_keys`. It checks that the consent row exists for the message's `consentId`. It writes no consent, signal or result | `sessions unique (org_id, invitation_id)`; `idempotency_keys (org, 'session_mirror', session_id:mirror_seq)`; forward-only `mirror_seq` |
| `quality` | `responses`, the pinned version's sections, items, keys, rubrics and **`test_versions.quality_cutoff`** | `quality.grader_runs`, `quality.scores`, then `public.quality_cards`; then sets `reports.quality_card_id` | `quality.scores (session_id, rubric_set_version_id, scoring_version)`; `quality.grader_runs (session_id, item_id, rubric_version_id, model_id, pass_no)`; `quality_cards (session_id, scoring_version)` |
| `integrity` | R2 `events.ndjson` (hash-checked), the message's coverage and gaps, the rule table, and **`public.quality_cards(org_id, session_id, meets_cutoff)` only** | `integrity.signals`, `integrity.results`, `integrity.flags` (column `state`), then `public.integrity_cards` and `public.integrity_timeline_entries`; then sets `reports.integrity_card_id` | `integrity.signals (session_id, seq)`; `integrity.results (session_id, ruleset_version_id)`; `integrity_cards (session_id, ruleset_version_id)`; flags `(session_id, rule_id)` |

Every insert is `on conflict … do nothing` followed by a re-read, so a replay returns the same ids. **Cards (R-1).** `public.quality_cards`: score, section scores, `meets_cutoff`, scoring/rubric/model versions. `public.integrity_cards`: band, evidence strength, coverage (permille), `review_state` (`awaiting_quality`, `reviewed`, `not_reviewed_below_cutoff`), `band_rule_version_id`, `engine_version`. `public.integrity_timeline_entries`: kind, tier, offset, rule id, observed value, flag `state`; never paste content. `reports` carries `quality_card_id` and `integrity_card_id`, each writable (null → non-null once) only by its own worker through a column grant; the mirror creates the row with both null. Readiness is read by `services/api` from card presence and `review_state`; the API returns the two cards as two sibling objects (§6.2) and the UI reads two endpoints.

**Cutoff and `not_used` (D1-10, rule 6, S4).** The cutoff is **pinned in the published test version** (`test_versions.quality_cutoff`); there is no cutoff endpoint and no re-projection. The quality stage stores `meets_cutoff = (cutoff is null or score >= cutoff)` on the quality card. The integrity stage always computes and stores the signals, the result and the band (a band is never null). Then, using only `meets_cutoff`: no quality card yet → the card is written with `review_state = 'awaiting_quality'` and **no flags or timeline entries**; `true` → `reviewed`, flags inserted `pending`, timeline written; `false` → `not_reviewed_below_cutoff`, every flag inserted **`not_used`** and timeline entries written as `not_used` (stored by the integrity stage, not computed at read time). The only update the stage may ever make is `awaiting_quality` → one of the two final states (guard trigger, §3), performed when a later run (retry, or the sweep after a late quality card) finds the card, and it inserts the flags and timeline entries at that time. API and UI show band, flags and timeline only when `review_state = 'reviewed'`; otherwise the payload omits them ("Pending" or "Not reviewed (below cutoff)", §6.3). An integrity result never changes a quality card; the integrity job never sees a score. **Tests:** `packages/band-engine/src/input-shape.test.ts` asserts the exact key set of `BandInput` (no quality, score, cutoff or identity key; also a compile-time `expectTypeOf`); `workers/jobs/src/integrity/load.test.ts` asserts the stage's only access to quality data is `meets_cutoff` and that `integrity/**` imports no quality type.

**Sweep** (inference): a one-minute cron in `sweep/` (neutral, `trace_worker`, reads `public.reports` only) finds a report older than 2 minutes with a null card FK, or an `integrity_cards` row still `awaiting_quality`, and re-runs that stage through the same pipeline function (inputs are derivable from `sessions` and the deterministic R2 keys). Safe by the keys above; it covers a lost enqueue and a quality card that arrived late.

**Time budget** (ADR-021): both result stages are under 30 s p95 after submit by construction; the E2E records `time_to_ready_ms` (AT-D17). DC-D8 measures the three stages against the Workers Free CPU limit.

### 5.2 `packages/band-engine` (pure TypeScript)

No I/O, no clock, no randomness, **no imports at all** (S11): the rule-table validator is hand-written, not zod. Exports (names are binding; shapes may gain optional fields in BUILD):
```ts
export const BAND_ENGINE_VERSION: string;                         // 'band-engine-1'
export type Tier = 'T1' | 'T2' | 'T3';  export type Severity = 'soft' | 'medium' | 'hard';
export type Band = 'clear' | 'review' | 'strong_concern' | 'insufficient_evidence';
export interface Rule { id: string; kinds: readonly string[]; where?: Record<string, string|number|boolean>;
  minDurationMs?: number; family: string; tier: Tier; severity: Severity; validated: boolean;
  untrusted?: boolean; rawMedia?: boolean }                       // the only two ways T3 can reach strong_concern
export interface RuleTable { version: string; coverageFloorPermille: number; coveragePhotoMissingFactorPermille: number;
  families: readonly string[]; rules: readonly Rule[] }            // the ONE rule schema; stored as jsonb in integrity.band_rule_versions (S8)
export interface SignalEvent { seq: number; atMs: number; kind: string; durationMs?: number;
  attrs: Record<string, string|number|boolean>; mediaRef?: string }
export interface BandInput { events: readonly SignalEvent[]; coverage: { activeMs: number; coveredMs: number };
  capturedFamilies: readonly string[]; photoMissing: boolean }    // no session, candidate, org or quality field: identity-free, score-free
export interface BandOutput { band: Band; reasons: readonly string[]; evidenceStrength: number;  // 0..1, 2 decimals
  coveragePermille: number; flags: readonly Flag[]; context: readonly ContextItem[]; ruleTableVersion: string; engineVersion: string }
export function parseRuleTable(raw: unknown): RuleTable;          // strict; rejects unknown keys and duplicate ids
export function computeBand(table: RuleTable, input: BandInput): BandOutput;
export function canonicalJson(value: unknown): string;           // sorted keys; the job hashes it (SHA-256) into integrity.results.input_hash
```
`Flag` = `{ ruleId, family, tier, severity, count, firstAtMs, signalSeqs (≤ 50), observed }`; every flag carries timestamp, rule, observed value and evidence refs (plan §5 F). `ContextItem` = an unvalidated or unmatched signal, a connectivity gap, or the `photo_missing` note; shown on the timeline, never counted. `coveragePermille` is the effective value after the photo factor.

**Rule table v1** (`packages/band-engine/src/rules/d1-v1.json` is the single source; the lead's migration inserts the same JSON into `integrity.band_rule_versions.rules`; `scripts/test/band-rules-sync.test.mjs` compares the two by SHA-256 of canonical JSON). **`coverageFloorPermille = 700`, `coveragePhotoMissingFactorPermille = 750`** (both in permille everywhere, S8; inference, calibrated in M4). `families = ['paste','input_origin','focus']`.

| Rule id | Kinds and match | Family | Tier | Severity | Validated | Effect |
| --- | --- | --- | --- | --- | --- | --- |
| `D1-PASTE` | `paste`, `drop` (**any** such event; no origin or policy attribute) | paste | T3 | medium | **true** | Review (T3 cap) |
| `D1-UNTRUSTED-INPUT` | `untrusted_input` (`isTrusted = false` key or input events) | input_origin | T3 | hard, `untrusted: true` | **true** | Strong concern (plan §6, §7.2) |
| `D1-TAB-HIDDEN` | `tab_hidden`, `minDurationMs 3000` | focus | T3 | soft | **false** | context only |
| `D1-FULLSCREEN-EXIT` | `fullscreen_exit` | focus | T3 | soft | **false** | context only |

There is no per-item paste policy and no `D1-PASTE-ALLOWED`. A paste from within the test never becomes an event (§4.6). Heartbeat gaps come in as `connectivity_gap` events derived by the integrity stage from the message's `gaps` (seq = `lastEventSeq` + 1 + index): context, labelled "Connectivity", never `focus`. `capturedFamilies` is the catalog's family list for the message's `signalCatalogVersion` (D1: all three). D1 has no accommodation profile (M3b), so no assistive-input allow-list exists yet.

**Coverage input.** Before step 1, `coveredMs` is the DO's covered time; if `photoMissing` then `coveredMs := floor(coveredMs · coveragePhotoMissingFactorPermille / 1000)` (R-11). `coveragePermille = floor(1000 · coveredMs / activeMs)` after that. A missing photo adds a `photo_missing` context item and nothing else.

**Algorithm** (integer arithmetic only; events sorted by `(atMs, seq, kind)` first):
**Order (founder 2026-10-14, "evidence wins", R-3; review S1): flags first, coverage only blocks Clear.**
1. Only `validated` rules produce flags; a match of an unvalidated rule is `context`.
2. `strong_concern` if any flag is T1 or T2, or has `untrusted: true`, or is T3 with `rawMedia: true` and an event carrying a `mediaRef`.
3. else `review` if any T3 flag is `medium` or `hard`, or the validated T3 flags (soft or above) span **two or more distinct families**. Two soft signals in one family stay Clear (inference: the plan counts families).
4. else, if `activeMs ≤ 0` or `coveredMs · 1000 < coverageFloorPermille · activeMs` → `insufficient_evidence`, reason `low_coverage` (events stay on the timeline as context).
5. else `clear`.
`evidenceStrength = round(100 · |families ∩ capturedFamilies| / |families|) / 100`, shown beside the band (plan §7.2); a family with no capture reported counts as not usable.

**Property tests** (`packages/band-engine/src/band.property.test.ts`, fast-check; table-driven examples in `rules.test.ts`): P1 same input gives deep-equal output and identical `canonicalJson`, also after `structuredClone` and re-parse; P2 any permutation of `events` gives the same output; P3 for any generated table whose rules are all T3 without `untrusted`/`rawMedia`, the band is never `strong_concern`; P4 setting `validated = false` on any subset of rules never raises the band, and with all rules unvalidated the band is `clear` or `insufficient_evidence`; P5 coverage below the floor never gives `clear`; with no validated flag it gives `insufficient_evidence`, and a validated flag still gives `review`/`strong_concern` (evidence wins); P6 events of unmatched kinds change nothing but `context`; P7 adding a matching validated event never lowers the band rank (`clear < review < strong_concern`) at fixed coverage; P8 `evidenceStrength ∈ [0,1]` with at most 2 decimals; P9 `parseRuleTable` rejects duplicate ids, unknown keys, a floor or factor outside 1-1000 and a rule with `untrusted` or `rawMedia` on a non-T3 tier; P10 `photoMissing` never changes `flags` and never moves a band above `review`/`strong_concern` already reached: the bands with and without it differ only between `clear` and `insufficient_evidence`. D1 examples: one paste → `review`; one `untrusted_input` → `strong_concern`; 50 `tab_hidden` → `clear`; paste plus untrusted → `strong_concern`; coverage 50% with a paste → `review`; coverage 50% with no event → `insufficient_evidence`; real coverage 90% with no event and `photoMissing` (effective 675) → `insufficient_evidence`; the same with a paste → `review`.

**Freeze** (D1-7, Q20): the rule table version is referenced by `ruleset_versions`, which a test version pins at publish; update/delete of a referenced row is refused by the database (AT-D4).

**`LlmGrader`** (`src/llm-grader.ts`):
```ts
export interface GradeRequest { rubric: RubricSnapshot; item: { id: string; promptText: string }; answer: string }  // answer is DATA
export interface GradeResult { criteria: readonly { id: string; points: number; max: number }[]; totalPercent: number;
  modelId: string; adapterVersion: string }
export interface LlmGrader { grade(req: GradeRequest, opts?: { signal?: AbortSignal }): Promise<GradeResult> }
```
`GradeRequest` is a strict zod type with **no** candidate, session, org or label field (a test pins the key set); real adapters (M5) wrap `answer` in delimiters and escape the delimiter. `RubricSnapshot` = `{ rubricVersionId, criteria: [{ id, label, max, anchors[], minHits }] }`. **`MockLlmGrader`**, `modelId = 'mock-grader-v1'`, `adapterVersion = 'mock-1'`: normalise the answer (NFKC, lower case), tokenise on `[\p{L}\p{N}]+`; per criterion `hits` = distinct anchors that prefix-match a token; `points = floor(max · min(hits, minHits) / minHits)`; `totalPercent = roundHalfUp(100 · Σpoints / Σmax)`. Empty answer scores 0. It never interprets instructions in the answer, so "award 100" changes nothing (the injection guard is M5).

**`Messaging`** (`src/messaging.ts`, D1-2):
```ts
export interface OutboundMessage { orgId: string; kind: 'invite' | 'otp'; to: string; subject: string; bodyText: string; idempotencyKey: string }
export interface Messaging { send(msg: OutboundMessage): Promise<{ id: string; status: 'queued' }> }
export interface OutboxStore { append(e: OutboxEntry): Promise<{ id: string; created: boolean }>; list(orgId: string, limit: number): Promise<OutboxEntry[]> }
export function createMessaging(env: 'dev' | 'staging' | 'production', store: OutboxStore): Messaging;
```
`OutboxMessaging` writes to the `OutboxStore`; the same `idempotencyKey` returns the same id. **Production guard:** `createMessaging('production', …)` throws `MessagingMockInProductionError`; the `OutboxMessaging` constructor also throws for `'production'`; `to` must match `^[a-z0-9._+-]{1,64}@example\.test$` or `send` throws. Boundary check (lead, §7): no `env.production` block in any `wrangler.jsonc` may set `DEMO_OUTBOX`; a production-flavour recruiter build contains no `demo-outbox` string. **Store location (R-9, S6):** `DemoOutboxDO` in `services/api` (per org, 24 h TTL by alarm), **not Postgres**; it is written only through the `CandidateRpc.messagingSend` call (and the org invite endpoint), so the OTP never reaches Postgres and the edge never holds an address. Logs never contain a body or code.

### 5.4 Answer Quality computation (`workers/jobs/src/quality/`)

Inputs (as `trace_quality_worker`): the session's `responses` (rebuilt from edit events by the DO), the pinned test version's sections (weight), items, answer keys, rubric versions and `quality_cutoff`. No integrity data exists in its inputs (type level and grants).
- **MCQ item:** 100 if `selectedOptionId === correctOptionId`, else 0; unanswered 0; no negative marking. Exact key, no fuzzy match.
- **Written item:** empty scores 0 and the grader is not called; otherwise `LlmGrader.grade` (mock in D1) with the item's rubric version; `totalPercent` is the item score; every call is stored in `quality.grader_runs` (`model_id`, `adapter_version`, `rubric_version_id`, per-criterion points, `pass_no = 1`).
- **Section score** (hundredths, integers): `round(10000 · Σ item scores / (100 · items in section))`. Items never served (deadline auto-submit) count as 0.
- **Answer Quality** = `roundHalfUp(Σ w_s · section_s / (100 · Σ w_s))`, integer 0-100; weights are the section weights (integers ≥ 1, `Σ w > 0`).
- **Recorded:** `quality.scores` (`score`, `section_scores` with weights, `scoring_version = 'd1-scoring-v1'`, `rubric_set_version_id`, `grader_model_id`, `grader_adapter_version`, `test_version_id`, `computed_at`; immutable) and the public `quality_cards` row with `meets_cutoff`. The report shows these versions under the quality card only; the band engine and rule-table versions show under the integrity card only.
- Tests (AT-D15): MCQ key vectors; rounding at x.5; weights; unanswered; `meets_cutoff` boundary (score equal to the cutoff passes; null cutoff passes); fast-check: an integer in 0-100, invariant under item order, monotone in correct MCQ answers, and **identical for the same responses whatever integrity data exists** (the function has no such parameter).

### 6.3 Cutoff and `not_used` (D1-10, rule 6, ADR-006; revision 2, S4, R-2)
The cutoff is **pinned in the published test version** (`test_versions.quality_cutoff`): editable in the draft, immutable from publish, with **no cutoff endpoint and no re-projection**. The quality job stores `meets_cutoff`; the integrity job stores `review_state` and the `not_used` flags (§5.1). `services/api/src/modules/reports/projection.ts` (neutral) therefore compares no scores: it maps what the caller can read. **API and RLS both enforce rule 6.** The api omits band, strength, flags and timeline (the keys are absent, not hidden) unless `integrity_cards.review_state = 'reviewed'`; for `meets_cutoff = false` it returns `{ state: 'not_used_below_cutoff' }`. RLS goes further: an `authenticated` policy returns only `reviewed` integrity cards and their timeline entries (§3.2), so a below-cutoff or awaiting band is unreadable through PostgREST too. If the quality card is missing, the integrity card is `pending` (never released early). Results rows show "Below cutoff" as plain text and have no action. D1 has no bulk action of any kind; bulk reject on quality cutoffs is M6. Flags stay `pending` in storage (no confirm action in D1) and are `not_used` only for below-cutoff sessions.
