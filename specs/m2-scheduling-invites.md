## 1. Scope

### 1.1 Build-order text
ABH-13 bulk invite (CSV/Excel, dedupe by phone/email) · ABH-14 drives, slots, capacity, 15-min start window, lobby 30 min early · ABH-15 reminders + one self-reschedule. `Messaging` interface: email (SES) first; SMS (DLT) and WhatsApp adapters behind flags. H: domain bought (done: `tracehiring.tech`), SES domain verified (done, sandbox) and production access requested (not yet), DLT + WhatsApp registration started (ABH-83, long lead).

**Exit gate:** 2,000 invites queued and delivered (sandbox) < 10 min with per-candidate status; duplicate rows rejected with reasons; reminders fire at the right times in a time-travel test.

## 4. State machines
- **Drive:** `draft → scheduled` (needs ≥1 slot for `scheduled` mode, pool ratio for `scheduled`) `→ closed` (manual, or after `deadline_at` by `private.close_due_drives` in the messaging claim stage, R5-6) · `draft|scheduled → cancelled` (cancels planned messages; invitations go `revoked` only by an explicit, audited recruiter action (single or bulk), never automatically; R5-13).
- **Slot:** `open → closed` (full is not a state; it is `booked = capacity`) · `open → cancelled` only when `booked = 0`.
- **Invitation:** D1 states and their forward-only order are unchanged (no `rejected`, rule 2). M2 adds slot moves, which never move the status: a recruiter may move an invitation in `created` or `sent`; the candidate's self-reschedule is allowed in `created`, `sent` or `otp_verified` (after a missed window the status stays `otp_verified` and the new slot's window applies). `started`, `submitted`, `expired`, `revoked` and `blocked_age` cannot be moved.
- **Outbound message:** `planned → queued → sent → delivered | bounced | complained`; `queued|sent → failed` (after 8 attempts or a permanent error); `planned → cancelled`.
- **Upload:** `open → completed | cancelled`.

## 6. Feature behaviour

### 6.1 Drives and slots (ABH-14)
`/drives/new`: test + version (published only), mode, window, reminder offsets (default 24 h + 1 h), self-reschedule toggle, lab mode; slots by list or generator. Publishing the drive (`draft → scheduled`) runs the pool-ratio check for `scheduled` mode. The drive page shows slots (booked/capacity), invitations with per-candidate status, and reminder plan per slot.

### 6.2 Bulk invite (ABH-13)
Template `trace-invites-v1.csv` (CSV only; `.xlsx` refused with "Save the sheet as CSV and upload that", R5-20) with columns `full_name, email, phone, 18_or_older, slot_starts_at (scheduled drives; blank = auto-assign the earliest slot with space, in file order), language`. Browser parses (≤ 5,000 rows, ≤ 5 MB), shows counts, posts batches of 200 with concurrency 2. **api per row:** zod shape → normalise (M2-4) → in-batch and in-upload duplicate detection by normalised value (the upload keeps a per-upload in-memory set within the request; across batches the DB index decides) → `adult18 = 'no'` → `minor` (nothing encrypted or stored) → encrypt name/email/phone with the org DEK, compute blind indexes and hints, compute the link token hash for `token_version = 1` → `ingest_invite_batch`. Response lists every row's outcome; the screen shows rejected rows (row number + reason in plain words, **never the cell value**) and held `phone_shared` rows with a "Mark as different people" action (R5-59). Cancelled uploads keep what was invited (each invitation can be revoked).

### 6.3 Messaging pipeline (Messaging interface; ABH-13, ABH-15)
`plan_messages` creates `planned` rows. **Cron** (`workers/jobs` scheduled handler, every minute, `trace_messaging_worker`): `claim_due_messages(now, 500)` → enqueue ids to Queue `trace-messages` (batches of 50). **Consumer:** per message: load pins and ciphertext → unwrap DEK (cache ≤ 5 min per isolate) → decrypt recipient and first name in memory → for `invite`/`reschedule` only: generate a random 256-bit link token and call `private.rotate_link_for_send` with its SHA-256 (R2-4; reminders carry no link) → render the template (no HTML injection: variables are text-escaped into a fixed HTML skeleton and a text part) → `Messaging.send` with the idempotency key → mark `sent` + `provider_message_id`; transient errors retry with backoff (Queue retry, max 8 attempts) → `failed`. Rate limit per org and channel (SES account send rate read from config; default 14/s once out of sandbox, 1/s in sandbox; the load-sim adapter declares 50/s). **Nothing decrypted is logged; errors carry codes only.** OTP emails (D1 `MessagingSend` RPC) switch from the demo outbox to the configured email adapter for drive invitations; D1 ad-hoc `@example.test` invitations keep the outbox.

### 6.5 Lobby, start window and late arrival (ABH-14)
**The start path is R5-63 and R5-66** (D1's path plus a window check; it wins over this paragraph where they differ). `invite/resolve` (D1, edge → api) returns `schedule` with its `phase` (R5-23, R5-64 b). Before `lobbyOpensAt`: `phase = 'wait_lobby'` with the time (no OTP sent). In the lobby window: OTP (purpose `lobby`, bound at issue, R5-19) → age → consent → photo (D1 order) → start with the lobby token (valid until `na + 60 s` for drive rows). api `sessionGrant` refuses a first start outside the window — scheduled `[starts_at, starts_at + start_window_minutes]`, open window `[opens_at, drive_end]` — and returns `sw`; `SessionDO.start` re-checks `sw` by its own clock when it creates the session (409 `outside_start_window`); the OTP for 20k candidates is spread over the 30-minute lobby, not the start minute. After `na` without a start: `phase = 'window_missed'` → `reschedule_offer` if allowed and unused. OTP purpose `lobby` is refused outside the lobby window (`lobby_closed`) for invitations not yet started (a drive row whose SessionDO holds a session counts as started: `sessionLive`, R5-66 c), so OTP load is bounded to the lobby; a `started` drive invitation may use it until `session_grant_exp` to resume (R5-53); D1 rows keep `refuseDeadLink` (R5-64 a). Open-window drives: the lobby window is `[opens_at, drive_end]`. A missed window or a reschedule needs no re-grant: the next `sessionGrant` uses the current slot's window (R5-63).

### 6.6 Self-reschedule (ABH-15)
Candidate app screen `/i#<token>` → "Can't make this time?" (shown when allowed) → OTP (purpose `manage`, bound at issue, R5-19) → portal token (1,800 s, ADR-030 amendment R5-21) → `GET /v1/portal/slots` (future open slots of the same drive with `available` booleans) → `POST /v1/portal/reschedule { toSlotId }` (R5-24) → api `private.self_reschedule` → new invite message with the rotated link; the old link stops working (hash changed).
